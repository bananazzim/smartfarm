# 최적 배치 표 → 1인칭 시뮬레이터

표의 1위에는 주요 버튼, 나머지 행에는 작은 3D 보기 링크를 추가했다. 기존 4개 열·센서 배지·정렬은 유지한다. 링크로 진입하면 프리뷰를 건너뛰며 일반 메뉴 진입은 기존 프리뷰를 유지한다.

## 정확성과 안전성

기존 evaluation_context 결과의 센서 ID·순위·분석 대상과 온실·모드를 서명한 URL로 전달한다. 데이터 상태는 온실 치수, 센서 좌표/상태 및 실제 측정 행의 SHA-256으로 확인한다. 링크는 24시간 유효하다. 서버는 현재 결과에서도 같은 순위와 센서 ID 조합이 나오는지 확인한다. 변조·만료·다른 온실·모드·CSV/좌표 변경 시 블루 강조 없이 재선택 안내를 표시한다. URL highlight 값은 사용하지 않는다.

선택 조합을 세션에 저장하지 않는다. 따라서 다른 메뉴에서 정상 진입하면 비교 조합이 남지 않는다. 갱신 API URL에도 서명 링크를 보존하여 입장 후 다른 조합으로 바뀌지 않게 한다. 2위 이하의 화면 안내와 근접 정보는 비교 조합으로 표시하며 1위 추천이라고 부르지 않는다.

실제 센서는 기존 DB/이력 좌표 그대로 표시한다. DEMO 링크는 기존 최적화의 P1~P6 예시 좌표를 재사용하고 실제 CSV 데이터와 섞지 않는다. 최적화 수식·순위 산정·CSV 업로드·DB 스키마는 변경하지 않았다.

## 변경 파일

- optimization/simulator_links.py: 서명 링크와 데이터 상태 검증용 해시.
- optimization/views.py: 계산 결과 행에 링크 추가.
- templates/optimization/results.html: 1위 버튼 및 다른 행의 작은 링크, 해당 액션 스타일.
- visualization/views.py: 서명·온실·모드·데이터·현재 결과 검증, 선택 조합과 즉시 입장 플래그 전달.
- static/js/fps-bootstrap.js: 즉시 입장 및 선택 조합 안내.
- static/js/simulator-fps.js: 비교 조합용 목록·근접 정보 문구.
- templates/visualization/simulator.html: 탐색 화면의 작은 조합 안내.
- optimization/test_selection.py: 서명, 실제/DEMO, 다른 온실·모드, 변조 및 데이터 변경 검사.
- backups/scene-fix-fbfb02df/browser_check.py: 실제 브라우저 직접 진입 검사.

## 검증

관련 Django 21개 통과. JS 근접/데이터/경로 검사 및 변경 모듈 문법 검사 통과.

Chrome에서 실제 1위 S03/S07/S08, 2위 S03/S06/S07, DEMO 1위 P2/P3/P4, 2위 P1/P5/P6 각각 즉시 입장 및 정확한 블루 강조 확인. 변조된 링크에서 강조 없음, 정상 메뉴 재진입 시 프리뷰 및 비교 상태 제거 확인. 자동 테스트에서 갱신 API의 조합 유지, 다른 온실·모드 차단, 측정 데이터 변경 시 링크 무효화 확인.

전체화면·이동·근접 표시 구조는 그대로 유지한다. 네이티브 Pointer Lock/ESC 실기 검증 제한은 기존과 동일하다.
