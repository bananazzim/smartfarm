# 3D 시뮬레이터 UI/UX 2차 개선 결과

## 1. 변경 파일

- `templates/visualization/simulator.html`: 개요 프리뷰, 동적 정보, 유형 범례, 입장·복귀 버튼, 숨겨진 탐색 화면.
- `visualization/views.py`: 센서 ID·유형별 중복 없는 개요 개수 전달.
- `static/js/fps-bootstrap.js`: overview/exploring 상태, 지연 로딩, 진입·종료, 데이터·시점·선택 보존.
- `static/js/simulator-fps.js`: 유형별 마커 재질, 라벨·목록 색상, 종료 상태 정리.
- `static/css/simulator-fps.css`: 개요 및 유형별 스타일. 모든 규칙은 FPS 래퍼 안에 한정.
- `visualization/test_fps.py`: 초기 개요 상태·에셋·동적 유형별 개수 테스트 추가.
- `static/images/greenhouse-isometric-preview.png`: 제공된 디자인 이미지 원본 복사.
- `docs/fps_ui_overview.md`, `docs/fps_integration.md`: 결과 및 최신 동작 안내.

브라우저 검수 스크립트는 기존 `backups/scene-fix-fbfb02df/browser_check.py`에 `--fps-overview-only` 검증을 추가했다.

## 2. 센서 색상

`positionType`만으로 결정한다. recommended는 **#DC3545**, measured는 **#737D86**이다. 구형 본체·후광·외곽 링·바닥 링·높이선, 목록의 점, HTML 라벨, 조준점과 선택 표시를 일관되게 변경했다.

선택은 외곽선·크기·펄스로 강조하고 측정 센서의 회색을 빨강으로 바꾸지 않는다. 동일 ID를 가진 measured/recommended도 독립적으로 표시한다. 실제 고객 데이터에 추천 위치가 없으므로 현재 개요는 실제 설치 8개/추천 위치 0개이며, 탐색 화면의 마커 8개가 모두 회색이다. 최적화 조합을 새 설치 좌표로 변환하거나 가짜 추천 마커를 만들지 않았다.

## 3. 프리뷰 에셋

제공된 `스크린샷 2026-10-31 125058.png`를 원본 그대로 복사했다. 경로는 `static/images/greenhouse-isometric-preview.png`, 크기는 **1074×1032px**이다. 복사본과 제공 파일의 바이트 일치도 확인했다.

object-fit:contain으로 비율을 유지하고 큰 중앙 카드에 표시한다. 카드 전체와 별도 ‘온실 내부 탐색하기’ 버튼을 모두 사용할 수 있다. 키보드 접근·포커스 표시를 유지하고 마우스 호버에 미세한 변화를 적용했다. 고객별 실제 건물이나 센서 위치를 보여주는 이미지가 아니라는 설명을 표시한다.

온실명·규격·측정 센서 수·추천 위치 수는 실제 Django 데이터로 표시한다. 반복 측정 행은 센서 개수로 중복 계산하지 않는다. 추천이 0개이거나 데이터가 비어 있어도 입장이 가능하다.

## 4. 페이지 전환

별도 URL을 추가하지 않았다. 같은 페이지에서 `data-view="overview"`와 `data-view="exploring"`을 전환한다.

1. 접속하면 개요만 표시한다.
2. 프리뷰 카드 또는 입장 버튼을 누르면 탐색 화면을 먼저 표시한다.
3. 레이아웃이 확보된 다음에만 Three.js 모듈을 불러오고 렌더러를 생성한다.
4. ‘개요로 돌아가기’를 누르면 탐색 인스턴스를 해제하고 같은 개요로 돌아간다.

입장 전에 3D 모듈 요청이나 렌더러 생성이 없음을 실제 Chrome 네트워크·상태 검사로 확인했다. 탐색 화면의 처음 위치로·전체화면·기존 조작·센서 목록/상세는 유지했다.

## 5. 수명주기

개요에서는 3D 인스턴스와 갱신 타이머를 유지하지 않는다. 입장할 때는 최신 위치 스냅샷을 읽고 한 번만 초기화한다. 중복 클릭과 로딩 도중 복귀는 세대 번호로 구분해 늦게 도착한 요청이 숨겨진 화면에 렌더러를 만들지 않게 했다.

복귀 시 전체화면을 종료하고 GSOSim.destroy()로 포인터 잠금, RAF, 이벤트, 옵저버, GPU 자원을 정리한다. 키 상태·속도 잔여값·자동 경로·드래그·잠금 CSS도 초기화한다. Bootstrap의 입장·복귀 이벤트는 한 번만 등록한다.

같은 데이터·온실을 유지하며 선택한 이력 시각과 센서/유형을 재입장 시 복원한다. 센서 복원 때문에 자동 이동이 시작되지 않도록 선택만 복원한다. 3회 반복 입장 후 geometry 98개/texture 1개로 동일한 것을 확인했다.

## 6. 기존 데이터와 기능 보호

CSV 업로드, Sensor/Measurement 모델, DB 스키마, 측정 이력 집계, 위치 검증, 최적화 알고리즘은 변경하지 않았다. 기존 `optimization_scene.html`과 공유 Three.js 모듈도 수정하지 않았다.

실제 모드의 복귀·재입장 후 S01~S08이 유지되고 DEMO 센서가 추가되지 않는 것을 확인했다. 이력 시점을 선택한 뒤 재입장해도 동일한 시점과 선택 센서가 유지된다. 원본 Claude HTML도 그대로다.

## 8. 남은 확인 사항

헤드리스 Chrome에서 네이티브 포인터 잠금을 허용하지 않아 잠금 상태의 실제 ESC 해제는 미검증이다. 전체화면 복귀, 잠금/키 상태 정리 코드와 드래그 시점 조작은 확인했다. 모든 실물 모바일·브라우저·GPU 환경을 검증한 것은 아니다.

앱 내 브라우저 도구 오류로 이미 승인된 별도 Chrome 프로필을 사용했다. 캡처는 `backups/scene-fix-fbfb02df/fps-overview.png`, `fps-overview-mobile.png`에 있다. 서버를 재시작하고 새로고침하면 `/simulator/`에서 개요가 먼저 나타난다.
